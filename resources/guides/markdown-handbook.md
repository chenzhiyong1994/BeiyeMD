# Markdown 写作手册

这份手册围绕“写得清楚、改得安全、交付时不出错”组织内容。你可以先在「预览」里专注写作，再切到「Markdown」核对原始符号和行号。

> 建议：先用标题列出骨架，再填正文。完成后运行右上角的「Markdown 检查」。

---

## 一、先搭好文档结构

```markdown
# 文档标题
## 背景与目标
### 当前问题
### 预期结果
## 方案
## 下一步
```

- 一篇文档通常只保留一个一级标题。
- 标题逐级递进，避免从 `##` 直接跳到 `####`。
- `#` 与标题文字之间需要一个空格。

## 二、段落、换行与分隔

段落之间留一个空行，能让源码和排版都更清晰。

```markdown
这是第一段。

这是第二段。

---

分隔线之后的新章节。
```

北页会显示自然换行；如果不同工具中的换行表现不一致，使用空行划分段落最稳妥。

## 三、强调文字

| 目的 | 写法 | 示例 |
| --- | --- | --- |
| 重要结论 | `**加粗**` | **需要确认** |
| 轻度强调 | `*斜体*` | *补充说明* |
| 已废弃内容 | `~~删除线~~` | ~~旧方案~~ |
| 待关注内容 | `==高亮==` | ==风险项== |
| 命令或字段 | `` `行内代码` `` | `npm run dev` |

需要显示语法符号本身时，在符号前添加反斜杠，例如 `\*不会变成斜体\*`。

## 四、列表与任务

```markdown
- 无序项目
  - 二级项目

1. 第一步
2. 第二步

- [ ] 待处理
- [x] 已完成
```

预览模式下可直接点击任务框；光标位于任务行时，也可以按 `Ctrl+Enter`（macOS 为 `⌘+Enter`）切换状态。

## 五、引用

```markdown
> 引用的第一段。
>
> 引用中也能使用 **强调**、列表和链接。
```

引用外部内容时，建议紧接着写明来源与上下文，避免信息脱离原意。

## 六、链接与图片

```markdown
[项目主页](https://github.com/chenzhiyong1994/BeiyeMD)

![界面说明](assets/workspace.png)
```

- 网络链接使用完整的 `https://` 地址。
- 本地图片适合放在文档旁的 `assets` 文件夹，并使用相对路径。
- 图片说明不要留空；图片加载失败时，它仍能说明原本内容。
- 预览模式中按住 `Ctrl`（macOS 为 `⌘`）点击链接，可在浏览器打开。
- 点击图片后，可在浮动工具栏调整宽度与左、中、右对齐。

## 七、代码

短命令放在行内：`npm run dev`。

多行代码使用围栏，并注明语言：

```javascript
function greet(name) {
  return `你好，${name}`
}
```

常用语言标识包括 `javascript`、`typescript`、`json`、`bash`、`css`。围栏开始与结束处都需要三个反引号。

## 八、表格

```markdown
| 项目 | 状态 | 负责人 |
| :--- | :---: | ---: |
| 编辑体验 | 进行中 | 小北 |
| 发布准备 | 待开始 | 叶子 |
```

分隔行同时决定对齐：`:---` 左对齐、`:---:` 居中、`---:` 右对齐。

预览模式中点击表格可打开浮动工具栏，增删或移动行列。拖动列边界可改变列宽，宽度会随文档一同保存。

## 九、数学公式

行内公式使用一对美元符号：`$E = mc^2$`。

独立公式使用双美元符号：

```markdown
$$
f(x) = \sum_{i=1}^{n} x_i
$$
```

也可以从「编辑 → 插入公式」打开三语公式对话框。

## 十、转义与常见错误

下面这些符号在行首或成对出现时具有特殊意义：

```markdown
\# 不是标题
\- 不是列表
\> 不是引用
\[不是链接\]
```

排版与预期不一致时，依次检查：

1. `**`、`~~`、反引号等成对符号是否闭合。
2. 标题与列表符号后是否有空格。
3. 段落之间是否留有空行。
4. 表格每行的列数是否相同。
5. 本地图片路径、文件名和大小写是否正确。
6. 代码围栏是否成对出现。

## 十一、可复用的起稿模板

```markdown
# 文档标题

用两三句话说明文档解决什么问题、面向谁。

## 背景

交代必要上下文。

## 目标

- [ ] 可验证的目标一
- [ ] 可验证的目标二

## 方案

### 主题一

内容……

### 主题二

内容……

## 结论与下一步

1. 明确结论。
2. 写下负责人和时间点。
```

---

最后切到「Markdown」检查原始符号与行号，再运行「Markdown 检查」核对标题、围栏、表格和本地图片。
