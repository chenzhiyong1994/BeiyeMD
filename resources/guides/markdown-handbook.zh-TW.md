# Markdown 寫作手冊

這份手冊圍繞「寫得清楚、改得安全、交付時不出錯」整理。你可以先在「預覽」中專注寫作，再切換到「原始碼」核對 Markdown 符號與行號。

> 建議：先用標題列出骨架，再填入正文，完成後執行右上角的「Markdown 檢查」。

---

## 一、先搭好文件結構

```markdown
# 文件標題
## 背景與目標
### 目前問題
### 預期結果
## 方案
## 下一步
```

- 一篇文件通常只保留一個一級標題。
- 標題應逐級遞進，避免從 `##` 直接跳到 `####`。
- `#` 與標題文字之間需要一個空格。

## 二、段落、換行與分隔

段落之間保留一個空行，能讓原始碼與排版都更容易閱讀。

```markdown
這是第一段。

這是第二段。

---

分隔線之後的新章節。
```

北頁會顯示自然換行；若不同工具的換行表現不一致，使用空行劃分段落最可靠。

## 三、強調文字

| 目的 | 寫法 | 範例 |
| --- | --- | --- |
| 重要結論 | `**粗體**` | **需要確認** |
| 輕度強調 | `*斜體*` | *補充說明* |
| 已淘汰內容 | `~~刪除線~~` | ~~舊方案~~ |
| 待關注內容 | `==醒目提示==` | ==風險項目== |
| 指令或欄位 | `` `行內程式碼` `` | `npm run dev` |

需要顯示語法符號本身時，在符號前加入反斜線，例如 `\*不會變成斜體\*`。

## 四、清單與工作項目

```markdown
- 無序項目
  - 第二層項目

1. 第一步
2. 第二步

- [ ] 待處理
- [x] 已完成
```

預覽模式下可直接點擊工作方塊；游標位於工作項目列時，也可按 `Ctrl+Enter`（macOS 為 `⌘+Enter`）切換狀態。

## 五、引用

```markdown
> 引用的第一段。
>
> 引用中也能使用 **強調**、清單與連結。
```

引用外部內容時，建議緊接著標明來源與必要上下文，避免資訊脫離原意。

## 六、連結與圖片

```markdown
[專案首頁](https://github.com/chenzhiyong1994/BeiyeMD)

![介面說明](assets/workspace.png)
```

- 網路連結使用完整的 `https://` 位址。
- 本機圖片適合放在文件旁的 `assets` 資料夾，並使用相對路徑。
- 圖片說明不要留空；圖片載入失敗時，它仍能說明原本內容。
- 在預覽模式中按住 `Ctrl`（macOS 為 `⌘`）點擊連結，可在瀏覽器開啟。
- 選取圖片後，可從浮動工具列調整寬度與靠左、置中、靠右對齊。

## 七、程式碼

短指令放在行內，例如 `npm run dev`。

多行程式碼使用圍欄，並標明語言：

```javascript
function greet(name) {
  return `你好，${name}`
}
```

常用語言標識包括 `javascript`、`typescript`、`json`、`bash`、`css`。圍欄開始與結束處都需要三個反引號。

## 八、表格

```markdown
| 項目 | 狀態 | 負責人 |
| :--- | :---: | ---: |
| 編輯體驗 | 進行中 | 小北 |
| 發布準備 | 尚未開始 | 葉子 |
```

分隔列同時決定對齊方式：`:---` 靠左、`:---:` 置中、`---:` 靠右。

在預覽模式中選取表格可開啟浮動工具列，新增、刪除或移動列與欄。拖曳欄界線可改變欄寬，北頁會將寬度與文件一同儲存。

## 九、數學公式

行內公式使用一對美元符號：`$E = mc^2$`。

獨立公式使用雙美元符號：

```markdown
$$
f(x) = \sum_{i=1}^{n} x_i
$$
```

也可以從「編輯 → 插入公式」開啟多語言公式對話框。

## 十、跳脫字元與常見錯誤

下列符號在行首或成對出現時具有特殊意義：

```markdown
\# 不是標題
\- 不是清單
\> 不是引用
\[不是連結\]
```

排版與預期不一致時，依序檢查：

1. `**`、`~~`、反引號等成對符號是否閉合。
2. 標題與清單符號後是否有空格。
3. 段落之間是否保留空行。
4. 表格每一列的欄數是否相同。
5. 本機圖片路徑、檔名與大小寫是否正確。
6. 程式碼圍欄是否成對出現。

## 十一、可重複使用的起稿範本

```markdown
# 文件標題

用兩三句話說明文件要解決什麼問題，以及文件的讀者是誰。

## 背景

交代必要的上下文。

## 目標

- [ ] 可驗證的目標一
- [ ] 可驗證的目標二

## 方案

### 主題一

內容……

### 主題二

內容……

## 結論與下一步

1. 明確寫下結論。
2. 記錄負責人與時間點。
```

---

交付前切換到「原始碼」檢查符號與行號，再執行「Markdown 檢查」核對標題、圍欄、表格與本機圖片。
